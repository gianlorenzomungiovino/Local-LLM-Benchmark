🧠 TASK: Build reproducible client-side benchmark repo for llama.cpp server

You are tasked with creating a minimal Python repository that benchmarks a locally running LLM server.

⚠️ IMPORTANT CONSTRAINT

The LLM server is:

NOT managed by this project
NOT started by this project
ALWAYS assumed to be already running manually by the user

Base URL will be provided at runtime, e.g.:

http://127.0.0.1:8080/v1/chat/completions
🎯 GOAL

Create a benchmarking system that:

Sends requests to a running OpenAI-compatible server
Evaluates multiple tasks deterministically
Sweeps sampling parameters
Stores all results for later comparison
⚙️ HARD REQUIREMENTS
1. No server management

❌ Do NOT implement:

server startup
docker orchestration
llama.cpp execution
model loading

✔ Only HTTP client logic

2. Tasks

Stored in:

/tasks/tasks.json

Format:

{
  "id": "string",
  "prompt": "string",
  "type": "qa | code | reasoning",
  "expected": "string"
}
3. Parameter grid

Stored in:

/configs/params.json

Each entry:

{
  "temperature": 0.0,
  "top_p": 1.0,
  "top_k": 0,
  "min_p": 0.0,
  "repeat_penalty": 1.0,
  "presence_penalty": 0.0
}

The system must iterate all combinations.

4. Execution logic

For each task × parameter set:

send request to:

POST /v1/chat/completions
payload:
{
  "messages": [
    { "role": "user", "content": "<prompt>" }
  ],
  "temperature": ...,
  "top_p": ...,
  "top_k": ...,
  "min_p": ...,
  "repeat_penalty": ...,
  "presence_penalty": ...
}
5. Evaluation (simple deterministic scoring)

Implement:

QA → substring match
Code → regex / substring match
Reasoning → keyword overlap score

Return:

{
  "score": 0.0 - 1.0,
  "notes": "short explanation"
}
6. OUTPUT FORMAT (CRITICAL)

Save everything in:

results/results.json

Each entry:

{
  "task_id": "...",
  "params": {...},
  "prompt": "...",
  "output": "...",
  "score": 0.0,
  "timestamp": "...",
  "model": "string (optional manual field)"
}
ALSO generate:
results/results.md

Must include:

table grouped by parameter set
average score per configuration
best configuration ranking
clear human-readable comparison
7. CLI

Single entrypoint:

python run.py

Optional arguments:

--server (default: http://127.0.0.1:8080)
--limit for debugging only
8. Repository structure
agent-bench/
  run.py
  llm_client.py
  evaluator.py
  runner.py
  configs/
    params.json
  tasks/
    tasks.json
  results/
🧠 DESIGN PRINCIPLES
Minimal codebase
No external frameworks
Fully deterministic evaluation
Designed for repeated experiments
Optimized for comparing sampling parameters
🎯 FINAL GOAL

The system must allow:

User starts llama.cpp server manually with any flags

User runs:

python run.py
System generates:
structured JSON results
readable markdown report
Results are comparable across runs
END TASK

Build the full repository accordingly.
